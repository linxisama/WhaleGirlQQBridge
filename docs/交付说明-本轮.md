## 一、一句话结论

市场里的 **512 个插件**能导入控制台并落在真正的 0.4 宿主根里跑（探针成功 510，两个必然不行的是 Electron 与缺 `skills/` 的那个）；**379 个 skill 包**能装、能分层，其中 **21 个 / 57 个工具**在「Node 内置模块政策 + ctx 注入」两道闸下真实可注册；控制台已通过 14 个 MCP 工具接入 DeepSeek Harness；本轮修掉 11 类真 bug，并把 5 份文档写齐（含本文件）。

## 三、用户机第一次启动还缺什么

| 缺什么 | 现象 | 怎么补 |
| --- | --- | --- |
| Python 3.12 依赖 | 启动即 import 报错 | `start.bat` 会自动建 venv 装 `requirements.qq.txt`；包内不带 wheel，首次需联网 |
| Node.js ≥ 20 | 扩展能装不能跑，`ensure_host_root` 返回 `{"ok": false, "error": {"code": "node-missing"}}` | 装 Node 20+ 后重启控制台（`runtime/qqagent-host/package.json` 的 engines 要求） |
| `config.qq.yaml` 里的模型/QQ 号 | 控制台起来了但不回话 | 配置模板只有 6 个键，需自填（API Key 一律不在包内） |
| 市场包本体 | 插件市场 / 技能市场首次打开是空的 | 把 `插件市场/` 与 `插件市场/Skill市场/` 放到程序目录同级，或设 `QQAGENT_SKILL_MARKET` / 配置 `qq_only.skill_market_dir` |
| 扩展运行时载荷 | 没有 `runtime/qqagent-host/` 时 P3 类扩展必崩 | 本包**已带**（272 文件 3.9MB），首次装扩展时自动物化到 `<data>/qq-only/qqagent_host` |

## 四、DSH 接入

- 控制台 HTTP 端点 → `tools/whale_bot_mcp.py`（stdio MCP）→ 写进 `~/.dsh/profiles/desktop/cordis.patch.yml` 的 `mcp-whale-bot` 入口。
- 14 个工具：`bot_status/bot_start/bot_stop/bot_plugins/bot_set_plugin/bot_personas/bot_activate_persona/bot_send_text/bot_market_list/bot_market_install/bot_extensions/bot_set_extension/bot_bridge_status/bot_skill_tools`。
- **装完必须完全退出 DSH 桌面版再启动**（MCP client 只在会话 scope 创建时拉一次，老会话不会出现这些工具）。
- 注册/卸载用 `tools/setup_dsh_memory.py`，写入前备份、第二次运行幂等；`tools/verify_whale_bot_mcp.py` 六项自检含 stdio 严格 UTF-8（Windows 中文系统默认 cp936 曾导致 DSH 报 `'utf-8' codec can't decode byte 0xb1`）。
