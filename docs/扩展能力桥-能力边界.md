# 扩展能力桥：能力边界

这份文档只回答一个问题：**哪些事这套桥永远做不到，为什么，证据在哪。** 不写"完全支持/全部兼容"；凡是做不到的地方直接写做不到。

配套文档：`docs/扩展能力桥-使用与排障.md`（怎么装、怎么查）。行号均指当前仓库版本（`src/plugins/qqagent_bridge.py` 1652 行、`src/extension_host.py` 484 行、`src/qq_app.py` 4694 行）。

---

## 1. 一页结论

| 能力 | 状态 | 依据 |
| --- | --- | --- |
| provider（`message.owner-check`/`llm.request-params`/`reply.local-policy`/`chat.ban-state`） | 可用，受事件与预算限制 | `src/plugins/qqagent_bridge.py:64` 白名单、`:75` `EVENT_BY_PROVIDER` |
| provider `message.gate`/`message.privilege-check`/`message.identity` | **0.4 宿主仍不调用；本控制台自己接了消费点**（门禁 / 主人提权 / 机器人身份） | 本文 §2；入口 `src/plugins/qqagent_bridge.py:1246`、`:1278`、`:1310`，消费点 `src/qq_app.py:1870`、`:734`、`:1898` |
| hook 六种（before-context/before-llm-messages/after-response/onMessage/before-tool/after-tool） | 有映射；before-tool/after-tool 还要靠工具环调用方 | `:101` `HOOK_EVENT` |
| 扩展"原地改 payload"的写法 | **必然丢失**（跨进程） | 本文 §3 |
| `reply.local-policy` 的 `shouldEnd` | **不可安全映射**，只记录不应用 | 本文 §4 |
| 需要 electron / 需要别的扩展 / 需要 OneBot 原生动作 | **做不到** | 本文 §5 |
| 工具枚举与调用（`list_tools`/`call_tool`） | 可用；单扩展独立进程 + 超时 | `:1234`、`:1309` |

## 2. `message.gate` / `message.privilege-check` / `message.identity`

**两条事实仍然成立：**

- 0.4 的权威能力表（`.tmp/qq-agent-ref/QQ-agent-main/0.4/doc/extend_development/plugin-development.md:218-286`「被核心消费的能力名」）里没有这三个名字；0.4 全树 grep `message.gate` 是 0 命中（`.tmp/inv/bridge-gap.md:339`）。复核结论：`.tmp/qq-agent-run/src` 里 `getCapabilityProviders` 的真实调用点只有 `message.owner-check`、`chat.ban-state`、`llm.endpoint-pick` 等，**没有这三个**。
- 桥不能"替宿主"调用它们，也不能凭扩展返回值伪造一条 0.4 里不存在的门禁。

**本控制台改的是另一半：自己在三个真实决策点上询问它们。** 0.4 没有给出返回值契约，所以"返回值怎么用"由这里定义，方向性是硬指标（`src/plugins/qqagent_bridge.py:1220-1225` 的注释是唯一权威口径）：

| provider | 消费点（本仓库） | 返回值怎么被消费 | 失败方向 |
| --- | --- | --- | --- |
| `message.gate` | `src/qq_app.py:1870`（`_work` 里 `run_on_prepare` 之后、"这轮要不要生成回复"之前） | `{block:true, reason}` 或市场 mention-skip 用的 `{skip:true, reason}` → 本轮不回复：`decision()` 写审计（带扩展 id 与原因）、消息 `state='blocked'`，模型一次都不调 | **fail-open**：桥关闭 / 没装扩展 / 扩展被停用 / 报错 / 超时 / 返回噪声 → 一律放行 |
| `message.privilege-check` | `src/qq_app.py:734`（`conversation_allowed` 私有分支，且只在"原判定不是主人"时问） | `{allow:true, reason}` → 这条消息按主人处理，并记一条 `self.note`（说明是谁提的权） | **fail-closed + 默认整条不派发**：桥设置 `privilegeEscalation` 默认 `False`，此时 `privilege_allow()` 直接返回 `allow=False`，**不起进程、不写账本**（`src/plugins/qqagent_bridge.py:1320`）；打开后也只有扩展明确 `allow=true` 才算提权，报错/超时/说否则一律否；既有主人判定在 `:730` 已经 return，扩展无法降级 |
| `message.identity` | `src/qq_app.py:1898`（人设解析之后、系统提示词构造之前） | `selfId` → 覆盖 `message['self_id']`；`nickname` → 系统提示词追加"群友平时叫你「…」"（`src/qq_app.py:1973`）；`persona` → 覆盖本轮自称 | **fail-open**：只认这三个**标量**键（`src/plugins/qqagent_bridge.py:598` `IDENTITY_OVERRIDE_KEYS`），函数值/未知键忽略；报错/超时/不返回 → 用原值 |

派发完全复用桥既有那一条通道，没有第二个子进程入口：`_provider_profiles()`（`src/plugins/qqagent_bridge.py:1226`）→ `_event_profiles()`（`:999`：先过 `enabled`，再按 `extension_registry` 过滤停用的扩展）→ `stage_payload()` 造载荷 → `extension_host.run_capability` 起单个 node 子进程。超时同时受 profile 的 `timeout` 与 `preAiBudgetMs` 预算约束，超时按上表方向性处理，不会拖住回复。

**仍然存在的边界（别读成"全部支持"）：**

- 三个 provider 只挂在 `on_prepare` 一个阶段（`src/plugins/qqagent_bridge.py:76` `EVENT_BY_PROVIDER`）：消息入库之后、模型调用之前问一次，模型已经在跑时无法再拦。
- `ownerOnly=True`（默认）时桥只对**主人**发来的消息派发这三个能力；要让陌生人也能被扩展判定，得关掉 `ownerOnly` —— 那是放宽既有安全设置，不作为默认值。
- `message.privilege-check` 只在私聊 `conversation_allowed` 里问；群聊白名单分支与 `can_send_proactive`（没有 sender_id）不派发。提权因此只作用于"私聊这个人算不算主人"。
- 市场侧声明与语义口径并不统一：`mention-skip` 返回的键是 `skip` 而不是 `block`（两个都认）；`probability-reply` 声明的是 `message.poke-gate`（不在白名单，桥不会调用）；`qq-identity` 返回的是 `{resolveUserId, describeMember, listMembers}` 函数表（标量覆盖时整体忽略，不会把函数拼进提示词）。WP1 清点口径是 `message.gate` 2 个扩展、`message.privilege-check` 1 个、`message.identity` 1 个（`.tmp/inv/wp1-report.md:78`）。
- `bridge_status().capabilities[i].deadInHost` 对这三项**不再是 `True`**（`src/plugins/qqagent_bridge.py:1633`，判据是 `HOST_CONSUMED_PROVIDERS` `:90`），控制台也就不再报"宿主不支持的能力 3 项"。配套文档 `docs/扩展能力桥-使用与排障.md:108-112` 已同步为接入后的说法（三个消费点位置、失败方向与设置项）。

## 3. 跨进程"原地修改"必然丢失

host-one.mjs 的执行模型：起一个 node 进程、`import()` 扩展、调用 `mod.hooks[hookName](payload)` 或 provider 函数，**只把返回值带回 Python**（`host-one.mjs:91-95` 打印 `__WHALE_JSON__` + JSON；`src/extension_host.py:76` `parse_host_stdout()` 解析）。

扩展若这样写，在 0.4 进程内有效、跨进程就是无效修改：

~~~javascript
// 原地改，什么都不 return —— 子进程退出后 payload 一起消失
hooks: { 'before-llm-messages': async (payload) => { payload.messages.push(extra) } }
~~~

实测口径（`.tmp/inv/wp1-report.md:156`）：扫描 159 次纯逻辑 `llm.request-params`/`before-llm-messages`/`after-response` 调用 —— **143 次返回 undefined、15 次返回原样 body、0 次返回被改过的数据**。

桥的对策是"返回即权威"：`stage_payload()`（`src/plugins/qqagent_bridge.py:430`）构造与 0.4 同名同形的 11 个字段，`apply_hook_result()`（`:459`）只在扩展**真返回了对象**时才改写 `messages`/`triggerEntries`/`response`/`block`/`arguments`/`result`。数据没变时账本仍写 `ok=true`（进程确实成功执行），但桥不假装修成功——这是刻意保留的可观测差异。

只有两条路能让原地修改生效，都不在本仓库权限内：改 host-one.mjs（仓库外禁改），或扩展作者改成 `return {messages}`。

## 4. `reply.local-policy` 的 `shouldEnd` 为什么不能映射

0.4 契约是 `{api, entries, batch} → {shouldEnd, budget, ...}`（`orchestrator.js:1231`），语义是"这一批回复就地收尾"。Python 侧最接近的挂点是 `on_post_reply`，而它的契约是**必须返回 str（最终回复文本）**（`src/plugins/manager.py:802`/`:814`）。

冲突点：

- `shouldEnd=True` 在 0.4 意味着"不再继续发送、就地结束这一批"；Python 侧唯一等价物是返回空串 —— 那会把**已经生成的整条回复静默丢弃**，用户看到机器人突然不说话。
- `budget` 之类字段在 Python 侧没有消费方。

所以桥只记录、不应用：市场实测 `early-finish`、`reply-guard` 返回 `{shouldEnd: false, reason: "…还没有发送动作…"}`（`.tmp/inv/wp1-report.md`）——连"该不该收尾"都依赖 0.4 内部的批次状态，Python 侧拿不到。

结论：**`reply.local-policy` 在桥里只有观测价值，没有控制价值**。

## 5. 三类外部依赖：结构上做不到

### 5.1 需要 electron（1 个）

唯一失败者 `long-image-reader`，`all-plugins-v4.json` 里 `ok=false`，原文（实测读取该 JSON 得到，另见 `.tmp/inv/bridge-gap.md:190`、`:268`）：

~~~text
注册失败：Cannot find package 'electron' imported from
D:\聊天机器人\qq机器人\.tmp\qq-agent-run\plugins-host-35488\_compat_one\index.js
~~~

桥跑的是纯 node 宿主，没有 electron 运行时；本仓库也不允许为此新增依赖，所以这是永久无解项。

### 5.2 需要别的扩展在同一宿主里（10 个）

`requires` 非空：`command.dispatch` 9 个、`currency.v1` 1 个、`memory-star.nodes` 1 个（按扩展去重 10 个，`.tmp/inv/bridge-gap.md:269`）。host-one.mjs 一次只挂**一个**扩展目录，被依赖方不在进程里，调用时必然拿不到。除非把宿主改成"一次加载 N 个扩展"，那会破坏当前的单扩展隔离与安全边界。

### 5.3 需要 OneBot 原生动作（1 个）

`permissions` 含 `onebot_call` 的 1 个扩展（`.tmp/inv/bridge-gap.md:267`）。控制台走官方 QQ 通道时没有对应 API；`src/plugin_capabilities.py` 的 `ONEBOT_ONLY` 集合已承认这批功能只有 OneBot 通道能做。

## 6. skill 侧的 T4 / T6 是什么

`src/skill_tools.py:77-82` 的 `BLOCKED_TIERS` 原文（结构性不可用，不加载、不重试）：

- `T4-host-source`：运行期要 `require("../../")` 0.4 宿主源码模块，本桥只把源码树当加载路径，工具执行期拿不到这些模块；
- `T6-disabled`：清单标结构性残缺（缺入口/清单/依赖），加载也不会成功。

配套 `DEFAULT_TIERS = ('T1-ready',)`（`:83`），默认只放行 T1。tier 的产生逻辑在 `src/extension_registry.py:349-382`（`host_imports` → T4、`requires` → `T5-depends-other`、`external` → `T2-web-fetch`、缺 zip 或加载失败 → `T6-disabled`）。

边界说明：T4 与"桥里能用"并非完全互斥——扩展装进**真宿主根**（含 `src/config.js` 的那份）后 `../../` 恰好两层深可解析，**能加载**（见使用文档 §1.1）。T4 说的是"不能只把源码树当加载路径"。

## 7. "511/512 可加载"的含义边界

真实含义只有一句：**在兼容宿主根下 `import` 探测成功**（`.tmp/inv/plugin-tools.md:13`、`.tmp/inv/sweep-report.md:16`、`:25`；唯一失败者 `long-image-reader`）。它不等于：

- 业务行为能在这套桥里发生（§3：原地修改 0/159 生效）；
- 每个 hook 都会被派发（before-tool/after-tool 需要工具环真调用 `manager.run_on_before_tool`/`run_on_after_tool`，桥不自造调用点）；
- 每个 provider 都会被 0.4 宿主询问（§2 的三类 0.4 宿主永远不会问；本控制台只给这三类补了自己的消费点，见 §2）；
- 声明的 `requires`/`onebot_call` 有可用环境（§5）。`web_fetch` 须单独看待：扩展工具已按清单 `permissions` 数组注入 `ctx.fetch`，未声明或非数组时给拒绝桩（`runtime/qqagent-host/host-one.mjs:39-46`、`:279-280`）；技能侧见 `runtime/qqagent-host/src/plugin-loader.js:124-126`。它不是“未实现 fetch”的结构阻塞，也不是对第三方代码的进程级网络隔离；目标可达性和业务调用仍须实测。本次当前市场818包/474个权限数组/157个 `web_fetch` 包；旧512包的108未复核（证据目录已清理），见 `docs/插件市场权限复核-20261105.md`、`docs/插件市场权限审计-20261105.json`。

同一份数据里的 "512" 只是清单条数（实测 `extension_host.discover_extensions(catalog.json)` 返回 512 条）。

## 8. 超时与隔离带来的硬限制

- 单扩展一个子进程（`asyncio.create_subprocess_exec`，`src/extension_host.py:130` `run_capability`）：跨扩展协作不可能；换来的好处是崩溃/死循环只影响自己。
- 超时上限 60 秒、下限 1 秒（`clamp_timeout()` `:51`、`MAX_TIMEOUT` `:38`）；超时即 kill 并记 `timed_out=true`（`:311` `_record`）。
- 同步链路有总预算 `preAiBudgetMs`（默认 1500 ms，取值的唯一入口是 `src/plugins/qqagent_bridge.py:924` `_budget_ms()`）：
  - `on_pre_ai` 是同步兜底（`src/plugins/qqagent_bridge.py:1149`；主链路实际走 `run_on_pre_ai_async`，`src/qq_app.py:1933`），预算用尽后本轮不再调用扩展；
  - §2 的三个新入口同样受它约束（`message_gate`/`message_identity` 走异步 `run_capability`，`privilege_allow` 走 `run_capability_sync`），`preAiBudgetMs=0` 时三者**都不派发**，行为与接入前完全一致。
