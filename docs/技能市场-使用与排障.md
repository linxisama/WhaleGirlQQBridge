# 技能市场：使用与排障

本文件讲控制台「技能市场」这一条线：包从哪来、装到哪、为什么某些包装上了也不注册、出问题先看哪里。
扩展（plugin）那一条线看 `docs/扩展能力桥-使用与排障.md`，两者共用「层级(T1–T6)」术语但落盘位置不同。

## 一、三个位置

| 是什么 | 在哪 | 谁决定 |
| --- | --- | --- |
| 市场 zip 目录 | 默认 `D:\聊天机器人\插件市场\Skill市场` | 环境变量 `QQAGENT_SKILL_MARKET`（历史名 `SKILL_MARKET_DIR` 同效）> 配置 `qq_only.skill_market_dir` > 默认候选（`src/skill_market.py:110` `_market_candidates`） |
| 已安装 skill | `<data>/qq-only/skill_extensions/<id>/` | `src/skill_tools.py:127` `extensions_dir(runtime)` |
| 清单快照 | `<data>/qq-only/skill-tools.json` | `src/skill_manifest.py:571` `ensure_manifest`（默认 `ttl=86400` 复用，`POST /api/skills/rescan` 强制重建） |

`<data>` 是控制台的数据根（桌面版实测 `C:\Users\<你>\AppData\Local\WhaleGirlQQ`），**不是**仓库里的 `data/`。
三个位置必须指向同一批包：市场目录换了却没重建清单，界面就会「列表换了、层级/可注册数还是旧的」。

## 二、装一个包会发生什么

1. 打开 zip 做安全体检：条目数 ≤4000、单包 ≤16MB、解压总量 ≤48MB，拒绝路径穿越 / 绝对路径 / 盘符 / 符号链接（`src/skill_market.py` `_open_archive`）。
2. 在临时目录解包，再原子 rename 到 `skill_extensions/<id>`；目标已存在时只有勾了「覆盖安装」（`force`）才替换，旧目录先挪成 `.old-<id>-<uuid>`，失败回滚。
3. 认清单 `skill.json`（市场里有 3 个老包只有 `plugin.json`，同样接受）；清单缺 `entry`/`main` 时回退 `index.js`。
4. 分层（T1–T6）后决定是否启用：`T4-host-source` / `T6-disabled` 或带阻塞原因的包**照常装好，但登记为停用**，返回里给中文 `note`；其余默认启用。
5. 启用 = 写进 `extension_registry` 的停用名单之外的集合；只有启用且层级允许的 skill 才会被工具环注册。

## 三、层级与「可注册」

层级是静态判定（不执行 JS）：读清单 + 静态扫入口源码里的 `registerTool` 调用。

| 层级 | 含义 | 会不会注册 |
| --- | --- | --- |
| T1-ready | 只用到宿主已注入的能力 | 会（默认唯一放行档） |
| T2-web-fetch | 需要外网（`fetch`） | 需显式 allow |
| T3-extra-api | 直连第三方 API | 需显式 allow |
| T4-host-source | 用 `../../src/*.js` 依赖 0.4 宿主源码 | 不会（结构性不可用） |
| T5-depends-other | 依赖别的扩展 | 不会 |
| T6-disabled | 结构性残缺：无清单 / 无入口 / 入口加载失败 / 一个工具都没有 | 不会 |

真实市场实测（379 个 zip）：T1 108 / T2 168 / T3 2 / T4 89 / T5 4 / T6 8。

T1 只是「能起进程跑」，不等于「会被注册」。注册还要过两道闸：

1. **Node 内置模块政策**（`src/skill_tools.py` `NODE_BUILTIN_SAFE` / `NODE_BUILTIN_GATED`）：
   `path/url/os/crypto/fs/fs\/promises` 等 17 项默认放行；`child_process/net/http/https/dgram/tls/worker_threads/vm`
   8 项必须由包自己声明对应 permissions 才放行（`child_process`→`process_spawn`，`net/http/https/dgram/tls`→`network`）。
   `fs` 进白名单是有意为之：`host-one.mjs` 用 `import()` 跑第三方 `index.js` 本身就是任意代码执行，
   注册期挡 `fs` 只是兼容性启发式，不是安全边界；真正想拦的是「能起子进程 / 直接出网」这两类会绕开账本、超时与审计的行为。
   真实市场里**没有任何包声明 `fs` 或 `process_spawn`**（permissions 词汇只有 `web_fetch` 157 / `onebot` 1 / `qq_sticker` 1），
   所以 gated 档今天是给将来留的口子，已经用一个包实测验证过「只改声明 → 从不可注册变为注册成功且真调用有结果」。
2. **ctx 成员**：宿主没注入的成员（`chatKey` 247 包 / `sender` 150 / `session` 126 / `onebot` 93 / `store` 90 / `kind` 89 / `emit` 64 / `chatId` 57）
   仍然挡死，静态正则也抓不到别名访问（`const c = ctx; c.chatKey`）。

上线两个闸之后，真实计数（生产函数 `register_skills` 口径，清单 376 条）：**可注册 21 个 skill / 57 个工具**，
全部是 T1。21 个是：`wiki-query`、`sanguosha-rules`、`memory-tidy`、`deai-flavor`、`memory-recall`、`hat-factory`、
`monster-hunter`、`bf1-knowledge-zh`、`battlefield-1-knowledge`、`dtcg-card-rules`、`rpg-gm`、`doc-workshop`、
`localchat-kit`、`sea-turtle-soup`、`trendy-memes`、`capability-guide`、`auto-backup`、`character-role`、
`rhythm-kb`、`budget-recipe`、`math-bank`。
把 `node:*` 全放能到 24 个 / 70 个工具，差的 3 个（`private-journal` 6 工具、`now-playing` 1、`ygo-kb` 6）
唯一被挡的就是 `node:child_process` —— 这是有意的取舍，不是漏放。

permissions 不能当安全边界（全库 103 个 skill 用了 OneBot 却一条权限没声明），放行粒度按「宿主实现了哪个 ctx API」。

## 四、HTTP 端点

读端点同时挂 GET 与 POST（控制台的 `run_api_async` 只发 POST）。

| 端点 | 返回要点 |
| --- | --- |
| `/api/skills/market` | `count/broken/market/tierFilled/items[{id,name,version,description,file,bytes,installed,tier,tools}]` |
| `/api/skills/installed` | `count/root/items[{id,path,name,version,entry,tier,tools,enabled,known,blocked}]` |
| `/api/skills/summary` | `installed/marketCount/eligible/blocked/marketDir`（清单没建过时 `eligible/blocked` 为 `null`，界面显示 —） |
| `POST /api/skills/install` | 入 `{file|zipPath, force, enable}`；出 `{ok,id,entry,files,bytes,replaced,tier,tools,enabled,note,error}` |
| `POST /api/skills/uninstall` | 入 `{id}`；`error.code` ∈ `bad-id|missing` |
| `POST /api/skills/rescan` | 强制重建清单，返回 `skills/elapsedMs/rebuilt/path` |

`enable` 三态：`true` 启用（受层级门禁）、`false` 明确停用、省略/其他 → `enable` 必须是布尔值才会被接受（非 bool 返回 400）。

## 五、排障决策树

**界面层级列是空的 / 「可注册」显示 —**
清单快照还没建过。点对话框里的「重建清单」（约 10–15 秒，379 个包），之后 24 小时内复用。
`summary` 这时给 `eligible=null` 是刻意的：没有快照就不能拿别的目录的数字冒充。

**装上了但工具环里没有它**
按顺序查：① `GET /api/skills/installed` 里 `enabled` 是否 true（T4/T6 会被门禁停用，看 `note`）；② `tier` 是否 T1（T2/T3 需要 allow）；③ 是否用了被挡的内置模块（`child_process` 等 8 项，见上一节；包可在 `skill.json` 的 `permissions` 里声明后重装）；④ 代码有没有用到宿主未注入的 ctx 成员（上一节 21 个可注册之外的多半卡在这）；⑤ 工具环总闸 `ai.tool_loop` 是否为 true（默认关闭，开启后首轮预热约 233ms）。

**同一批包，两个界面数字不一致**
先看 `summary.marketDir` 是否等于市场界面显示的那条路径。历史上 `src/skill_tools.py` 与 `src/skill_market.py` 各写了一套目录解析，现已统一（前者改为委托后者），并把 `runtime` 一路透传到清单读取。

**安装报错**
`exists` 已安装（勾覆盖安装）；`unsafe-path` 包内有穿越/绝对路径；`symlink` 包内有符号链接；`no-manifest` 缺 `skill.json`/`plugin.json`；`bad-id` ID 非法；`missing` 目标不存在；`too-many-entries` 条目超 4000。

## 六、本轮修掉的三处（口径变更，供回溯）

1. **市场目录双口径**：`src/skill_tools.market_dir()` 只认 `SKILL_MARKET_DIR` + 硬编码候选，`src/skill_market.market_dir()` 认 `QQAGENT_SKILL_MARKET` + 配置。后果：设了配置项时，界面列表扫目录 A、`rescan` 与清单读写扫目录 B（实测环境变量指向临时市场时，`rescan` 报 379 而不是 2）。现在 `skill_tools` 委托 `skill_market`，并接受两个环境变量名。
2. **清单读取不带 runtime**：`load_manifest()` 固定用默认数据目录，临时/多份数据下会读到别的目录的清单。现在 `_manifest_candidates/load_manifest/eligible_skills/_snapshot_index` 全部带 `runtime`。
3. **汇总用别的快照凑数字**：`summary` 在清单不存在时曾返回 376 这类与本市场无关的数字，现在给 `null`，界面显示 —；另加 `tierFilled` 字段与界面提示，引导先重建清单。
4. **市场层级与清单不同源**：`_snapshot_index` 曾走「数据目录优先、开发机 `.tmp/inv/skill-tools.json` 兜底」的自动探测，导致开发机看着有层级、用户机全空。现在只认 `data_dir(runtime)/skill-tools.json`，没有就返回空并由界面提示重建。

## 七、已知边界

- 静态扫描只认「清单 tools 数组 + `registerTool({...})` 对象字面量」，工厂函数/数组批量注册读不出来：全量对比参考清单，工具数 1080 vs 1149，32 个包逐包有差（`machine-work` 13→0、`jujutsu-phantom-parade` 0→6）。这是统计口径，不影响已识别的工具。
- `tierReason` 是新增字段，参考清单没有，别让下游拿它做判定。
- 判定顺序固定为 `no-manifest → no-entry → load-failed → no-tools → escape-run-root → T4 → T5 → T3 → T2 → T1`（T4 先于 T5、T3 先于 T2 是与参考对齐的关键）。
- 下游比对清单新旧请看 `stamp`，不要看 mtime（打包/解包会打乱 mtime）。
