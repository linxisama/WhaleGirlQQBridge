# 插件交接说明

> 读者：第三方插件作者、站方。
> 每条断言后面都标了源码位置（`file:line`），查不到的条目已删除，不写"大概/可能"。
> 内核的权威规格是 `docs/插件内核-API-v1.md`，本文只做交接层面的归纳，两者冲突以那份为准。

## 1. 这是什么

这是 Windows 上的 QQ 机器人控制台（`README.md:3`）。它里面**并存两条插件链，任何一条都不能替代另一条**：

| | 旧链（PluginBase 钩子） | 内核链（plugin_core） |
|---|---|---|
| 插件放哪 | 内置 `PLUGIN_MODULES`；用户插件在 `<数据目录>/custom_plugins/<id>/plugin.json` 或 `<数据目录>/custom_plugins/<id>.py` | `<账号数据目录>/plugin_core/plugins/<id>/plugin.json` |
| 清单字段 | 旧字段：`id` `api_version` `entry` 必填，`name` `description` `version` `permissions` `enabled_by_default` 可选 | 13 字段 manifest v1 |
| 扩展点 | `on_ingest` / `on_pre_ai` / `on_post_reply` 等钩子 | 只有 inbound / generate / outbound 三个挂载点 |
| 谁调度 | `PluginManager` 顺序调钩子 | `Host` + `Arbiter` 竞标仲裁 |
| 控制台在哪看 | 「插件」列表 | 「插件 → 内核插件」 |

依据：

- 旧链内置名单是 `src/plugins/manager.py:111-128` 的 `PLUGIN_MODULES`（冻结安装包再按 `BASIC_PLUGINS` 收窄，`src/plugins/manager.py:132-134`）；用户插件的两个落点是 `src/plugins/manager.py:418-419`（`custom_plugins_dir`）与 `src/plugins/manager.py:446-448`（`custom_plugin_path` = `<id>.py`）。
- 内核链的目录与数据目录：`src/plugin_core_bridge.py:4-5`（插件 `<账号数据目录>/plugin_core/plugins/<id>/plugin.json`，内核数据 `<账号数据目录>/plugin_core/data`）。
- 三个挂载点、没有任意 hook：`docs/插件内核-API-v1.md:10`。
- 「插件」列表只列旧链：`src/qq_app.py:6258-6264` 的 `GET /api/plugins` 直接取 `bot.plugins.list_plugins()`，没有合并内核插件。内核插件走 `/api/plugin-core/*`：`src/qq_app.py:6193`（status）、`:6205`（install）、`:6226`（uninstall）、`:6244`（reload）。控制台入口名「插件 → 内核插件」见 `README.md:61`。
- **有 `plugins.json`，但它只是对外索引，不是运行期事实**。仓库根的 `plugins.json` 给站方条目页渲染用，当前 `plugins` 为空数组（两套接口已定稿，还没有第三方插件登记）。运行期仍以磁盘目录为唯一事实：目录包不登记进 `custom_plugins.json`（`src/plugins/manager.py:414`），"目录包以磁盘上的 plugin.json 为唯一事实"写在 `src/plugins/manager.py:468-470`。新增第三方插件时除了放目录，还要在这个文件里补一条，否则站上页面看不到它。
- `plugin_packages/` 下 4 个内置包（`voice_console` / `pack-repeat-guard` / `pack-burst-merge` / `pack-sleep-quiet`）用的仍是旧字段，走旧链：例如 `plugin_packages/pack-burst-merge/plugin.json:2-15` 只有 `id` `name` `version` `api_version` `entry` `host` `min_host_version` `category` `enabled_by_default` `description` `permissions` `source`，没有内核要求的 `author` `capabilities` `side` `data_policy` `upstream` `native`；`plugin_packages/voice_console/plugin.json:1-17` 连 `api_version` 都没有。

## 2. 技术栈

| 层 | 是什么 | 依据 |
|---|---|---|
| 运行时 | Windows 10/11 x64、Python 3.12 | `README.md:25` |
| 内核包 | `plugin_core/`，纯标准库、零依赖，不 import 本仓库 `src/` | `plugin_core/README.md:3`、`docs/插件内核-API-v1.md:211` |
| 内核公开面 | `API_VERSION` / `Host` / `PluginContext` / `Bid` / `Action` / `Draft` / `load_plugins` / mock 三件套 | `plugin_core/README.md:40-45` |
| 接入层 | `src/plugin_core_bridge.py`：把内核 Host 接到 qq_app 运行时 | `src/plugin_core_bridge.py:1-9` |
| 旧链宿主 | `src/plugins/manager.py` 的 `PluginManager` | `src/plugins/manager.py:405` |
| 控制台后端 | FastAPI 路由，插件相关在 `src/qq_app.py:6193-6276` | `src/qq_app.py:6193`、`:6258` |
| 插件本体 | 目录 + `plugin.json` + 入口 `.py`，两种 manifest 各一套 | 本文第 3 节 |

内核包内部按职责切分（`docs/插件内核-API-v1.md:29-48`）：`manifest.py` 校验、`loader.py` 扫描与拒载、`sdk.py` 插件侧 API、`arbiter.py` 仲裁、`outbound.py` 出站管道、`permissions.py` 权限闸门、`actions.py` 动作执行、`store.py` KV、`audit.py` 审计、`host.py` 组装、`mock.py` mock、`cli.py`/`selftest.py` 命令行与自检。

## 3. 插件怎么被加载

### 3.1 旧链（PluginBase）

加载顺序固定为 **内置 → `custom_plugins.json` 登记的裸 `.py` → 目录 mod**，撞 id 时后者不顶掉前者（`src/plugins/manager.py:1395-1408`）。

- 裸 `.py`：文件是 `<数据目录>/custom_plugins/<id>.py`（`src/plugins/manager.py:446-448`），记账在 `<数据目录>/custom_plugins.json`（`src/plugins/manager.py:414`，读法见 `:451-461`）。
- 目录包（mod）：扫 `custom_plugins_dir`，**带 `plugin.json` 的子目录就是一个 mod**，自动挂载，不需要 `register_custom`（`src/plugins/manager.py:696-722`、`:724-742`）；没有 `plugin.json` 的子目录静默忽略（`src/plugins/manager.py:741-742`）。
- 两种拒载：与内置同名 `builtin_conflict`（`src/plugins/manager.py:749-752`）、同名裸 `.py` 存在 `file_conflict`（`src/plugins/manager.py:753-756`）。完整拒载码表见 `docs/插件接入契约-mod.md:56-68`。
- 旧字段：`id` `api_version` `entry` 必填，其余可选（`docs/插件接入契约-mod.md:28-37`）；最小清单只要三行（`docs/插件接入契约-mod.md:41-45`）。
- 钩子：`on_ingest` / `on_pre_ai` / `on_post_reply`（实例见 `src/plugins/keyword_reply.py:35`、`src/plugins/at_mention.py:76`），基类在 `src/plugins/__init__.py:89`。
- 运行期保护：钩子超时 2 秒（`src/plugins/manager.py:24`），连续 3 次失败自动禁用（`src/plugins/manager.py:26`，计数逻辑 `:1239-1256`；契约 `docs/插件接入契约-mod.md:72-76`）。

### 3.2 内核链（plugin_core）

- 目录：`<账号数据目录>/plugin_core/plugins/<id>/plugin.json`，目录名必须等于 `id`（`docs/插件内核-API-v1.md:8`；实现 `src/plugin_core_bridge.py:334`、校验 `plugin_core/manifest.py:111-112`）。
- 只有至少一个带 `plugin.json` 的子目录时才启动 Host，空目录不加启动开销（`src/plugin_core_bridge.py:6`、`:347-357`）；初始化失败不阻塞普通插件与 AI（`src/qq_app.py:611-617`）。
- **13 个必填字段**：`id` `name` `version` `api_version` `author` `description` `entry` `permissions` `capabilities` `side` `data_policy` `upstream` `native`（`plugin_core/api.py:51-65`，同 `docs/插件内核-API-v1.md:52-53`）；可选 `permission_flags` `storage` `config_schema`（`plugin_core/api.py:66`）。
- 逐字段校验：`id` kebab-case（`plugin_core/manifest.py:109-110`）、`id` 必须等于目录名（`:111-112`）、`version` semver（`:116-118`）、`api_version` 必须 int（`:121-122`）且**严格等于 1**（`:123-126`，`API_VERSION = 1` 在 `plugin_core/api.py:11`）、`entry` 是 `<相对路径>.py:<函数名>` 且**逃出插件目录即拒载**（`plugin_core/loader.py:60-63`）。
- 加载完立刻 **freeze**：`Host.start()` 走 preLaunch → load → enable → freeze（`plugin_core/host.py:208-255`），之后 `add_plugin` 抛 `FreezeViolation` 并写审计（`plugin_core/host.py:326-339`）；**唯一的重载方式是 `Host.reload_all()` 整批重载**（`plugin_core/host.py:290`，契约 `docs/插件内核-API-v1.md:23`）。
- 拒载码（`load-refused` 审计的 `code`，稳定不变，共 17 个，`docs/插件内核-API-v1.md:70-73` / `plugin_core/api.py:69-87`）：

  `bad-json` `bad-manifest` `missing-field` `bad-id` `id-mismatch` `bad-api-version` `api-version-mismatch` `entry-missing` `entry-escape` `bad-entry` `setup-error` `duplicate-id` `bad-permission` `bad-capability` `bad-data-policy` `bad-side` `bad-upstream`

  其中几个有直接实现锚点：`bad-json`（`plugin_core/manifest.py:207-209`）、`api-version-mismatch`（`plugin_core/manifest.py:123-126`）、`entry-escape` / `entry-missing` / `bad-entry`（`plugin_core/loader.py:60-80`）、`duplicate-id`（`plugin_core/loader.py:120`）、`setup-error`（`plugin_core/loader.py:137`、`:156`）。
- 注意两套拒载码不要混用：旧链目录 mod 用下划线风格（`bad_json` `missing_id` `entry_escape` `builtin_conflict` …，`docs/插件接入契约-mod.md:56-68`），内核链用连字符风格。

## 4. 一个插件能拿到什么

### 4.1 旧链

- 内置插件拿到活的 `QQRuntime`；**目录 mod 拿到的是只读门面 `ModRuntime`**，可访问成员只有 `mod_id` `api_version` `settings` `get()` `has_permission()` `log()` `note()` `now()`（`docs/插件接入契约-mod.md:84-92`），其它属性一律 `AttributeError`（`:94-97`）。
- 自己存数据用 `PluginBase` 的 `load_state` / `save_state`（`docs/插件接入契约-mod.md:99-102`）。
- `permissions` 在旧链**只是声明与查询**，主体不会因此自动放行或拦截具体动作（`docs/插件接入契约-mod.md:47-49`、`:169`）。
- `on_ready` 通道对 mod 关闭，返回里会被剥掉并记 `on-ready-stripped` 审计（`docs/插件接入契约-mod.md:106-111`）。
- 审计追加到 `<data_dir>/qq-only/plugin_audit.jsonl`，字段固定（`docs/插件接入契约-mod.md:115-121`）。

### 4.2 内核链

- `setup(api: PluginAPI) -> None` 里只登记、不产生副作用：`declare_inbound` / `declare_outbound` / `on` / `declare_command` / `declare_timer` / `can`（`docs/插件内核-API-v1.md:80-94`）。
- `Context` 只读（`__setattr__` 抛 `AttributeError`）：`session` `sender` `message` `plugin` `host` `cfg` `store` `can()` `log` `model.chat()` `fetch()`（`docs/插件内核-API-v1.md:102-118`）。字段已归一化，不允许任何字段直接来自上游原始报文（`:25`）。
- `ctx.model.chat` 只给 messages 与输出约束，不暴露 provider / endpoint / temperature（`docs/插件内核-API-v1.md:114-115`）；`ctx.fetch` 需要 `network` 权限，未声明抛 `PermissionDenied`（`:116-117`）。
- 产出只能是 `Action`：`send_text` `send_media` `store_set` `store_del` `schedule` `emit` `noop`（`docs/插件内核-API-v1.md:123-131`）。**插件返回动作列表，由主体校验权限后执行，插件不得自己发消息**（`docs/插件内核-API-v1.md:11`、`:21`）；动作→权限映射在 `plugin_core/permissions.py:10-14`。
- 权限五项与子标记：`read_message` / `send_message` / `store` / `network` / `admin`（`plugin_core/api.py:22`），子标记 `config_write`→`store`、`exec`→`admin`、`read_env`→`admin`（`plugin_core/api.py:30`，同 `docs/插件内核-API-v1.md:12-20`）。
- 调度语义：silent 与 main 同场按 priority 比较、main 同优先级按 manifest 声明序、attach 只在 main 胜出后跑、extra 独立发送、没 main 也没 extra 就什么都不发但仍写一条仲裁记录（`docs/插件内核-API-v1.md:139-150`；摘要 `plugin_core/README.md:52-58`）。竞标阶段**不调模型**，没声明 `read_message` 的插件不进入竞标（`docs/插件内核-API-v1.md:139-141`）。
- 出站管道：串行、priority 小的先执行、返回 `None` 即取消并短路、改写结果不再进管道（`docs/插件内核-API-v1.md:163-166`）。
- 落盘：`<data_dir>/plugin_kv/<plugin_id>.json`、`plugin_config/<plugin_id>.json`、`audit/<YYYYMMDD>.jsonl`、`session.json`（`plugin_core/README.md:62-67`）。

## 5. 不能做什么

**两条链各自的硬边界**

1. 内核链没有任意 hook，只有三个挂载点（`docs/插件内核-API-v1.md:10`）；旧链没有竞标/仲裁。想用钩子就只能走旧链，想用动作层权限校验就只能走内核链。
2. 内核链不支持单插件热重载，只有 `Host.reload_all()` 整批重载（`docs/插件内核-API-v1.md:23`；控制台 `/api/plugin-core/reload` 的注释原文「不做单插件热重载」，`src/qq_app.py:6244-6246`）。
3. `api_version` 不等于 1 直接拒载（`plugin_core/manifest.py:123-126`）；`entry` 越出插件目录直接拒载（`plugin_core/loader.py:60-63`）。
4. `permissions` 只能取那五项，含未知取值即 `bad-permission`（`plugin_core/permissions.py:26-29`）；`permission_flags` 只认 `config_write` / `exec` / `read_env`（`plugin_core/api.py:30`）。
5. 旧链目录 mod **不能发消息、不能调模型**，也没有 `on_ready` 让主体代执行代码（`docs/插件接入契约-mod.md:104`、`:170`）。
6. 旧链 mod 的 `permissions` 只是声明，不会自动放行/拦截（`docs/插件接入契约-mod.md:169`）。

**诚实边界（交付时必须原样传达，不许掩饰）**

7. **同进程 Python 插件不是安全沙箱**。内核侧：`network` / `exec` 只靠契约加动作层校验，插件若直接 `import requests` 内核拦不住，这是协作式限权，可机检的兜底只有 `selftest --only T5` 的静态扫描（`docs/插件内核-API-v1.md:249`、`plugin_core/README.md:71-72`）。
8. 旧链侧同理：`sys.modules`、栈帧、文件系统都可达，`ModRuntime` 挡的是误用，挡不住刻意绕过（例如直接 `import src.plugins.manager`）；要真隔离需要子进程/独立解释器，当前明确不做（`docs/插件接入契约-mod.md:163-166`）。
9. 同步钩子超时**不会杀掉线程**，只是主体不再等它（`docs/插件接入契约-mod.md:167-168`）。
10. 旧链 `reload()` 重建实例并把 `mod_revision` 无条件 +1，但**不清已建好的工具表**，失效靠下一次比修订号（`docs/插件接入契约-mod.md:171-179`，`src/plugins/manager.py:506-520`）。
11. 旧链增量同步的变更判据是 `(mtime_ns, size)`，被 `cp -p` / 解压 / `rsync --times` 回填时间戳就看不出改动（`docs/插件接入契约-mod.md:180-184`，`src/plugins/manager.py:1053-1060`）。
12. 插件之间不互相 import，通信只走 `emit` 动作 → `ctx.on(event)`（`docs/插件内核-API-v1.md:24`）。

## 6. 改完怎么交

### 6.1 目录结构

内核链（`docs/插件内核-API-v1.md:8`、`:237`）：

```
plugin_core/plugins/
  hello-mod/                 # 目录名必须等于 manifest 的 id
    plugin.json              # 13 字段 manifest
    plugin.py                # 入口，由 entry 指定
    README.md                # 怎么装 / 怎么触发 / 要什么权限
    demo.py                  # 一个能复现的最小脚本或测试
```

旧链目录 mod（`docs/插件接入契约-mod.md:13-17`）：

```
custom_plugins/
  my_mod/
    plugin.json
    entry.py
    data/...
```

### 6.2 最小 plugin.json

内核链（13 字段全给，缺一个就是 `missing-field`，`plugin_core/api.py:51-65`）：

```json
{
  "id": "hello-mod",
  "name": "打个招呼",
  "version": "0.1.0",
  "api_version": 1,
  "author": { "name": "你的名字", "contact": "QQ 或邮箱" },
  "description": "最小可加载示例",
  "entry": "plugin.py:setup",
  "permissions": ["read_message", "send_message"],
  "capabilities": [
    { "stage": "inbound", "produces": "main", "priority": 50 }
  ],
  "side": "both",
  "data_policy": "retain",
  "upstream": { "protocol": "onebot", "kernel": "plugin_core", "range": ">=3.2 <4" },
  "native": false
}
```

入口签名固定为 `def setup(api: PluginAPI) -> None`，`entry` 写法是 `<相对路径>.py:<函数名>`（`docs/插件内核-API-v1.md:60`）。`upstream.range` 不许空、不许写"最新版"（`:67`，校验 `plugin_core/manifest.py:84-96`）；`capabilities` 的 `produces` 与 `stage` 必须匹配，`exclusive` 只对 main、`requires_main` 只对 attach（`plugin_core/manifest.py:47-79`）。

旧链目录 mod（`docs/插件接入契约-mod.md:41-45`、`:127-134`）：

```json
{
  "id": "hello_mod",
  "api_version": 1,
  "entry": "entry.py",
  "name": "打个招呼",
  "version": "0.1.0",
  "permissions": ["read_message", "store_data"]
}
```

### 6.3 本地自检（提交前必须跑过）

```powershell
python -m plugin_core.cli demo                        # 竞标/胜出/落败 三行
python -m plugin_core.cli selftest --all              # T1..T10 逐项 PASS/FAIL
python -m plugin_core.cli selftest --only T8          # 单跑一项
python -m plugin_core.cli run --plugins <你的插件父目录> --data .tmp/run-data --message "在吗"
python -m unittest discover -s plugin_core/tests -t .
```

命令来自 `plugin_core/README.md:9-13`。`run` 会打印完整仲裁记录（`docs/插件内核-API-v1.md:209`），先看"几家竞标 / 谁胜出 / 落败原因"三件事对不对（`:159`）。T1–T10 各自断言什么见 `docs/插件内核-API-v1.md:215-226`。

旧链 mod 没有同等的 selftest，自检方式是：放进 `custom_plugins/` → 重启或重载 → 看运行记录里的加载问题与 `plugin_audit.jsonl`（`docs/插件接入契约-mod.md:51-54`、`:113-121`）。

### 6.4 提交什么

- 整个插件目录：`plugin.json` + 入口 `.py` + `README.md`（写清怎么装、怎么触发、要什么权限）+ 一个能复现的最小脚本（`docs/插件内核-API-v1.md:237`）。
- 不要提交 `__pycache__` / `*.pyc` / `.git`：安装器复制时会跳过它们（`src/plugin_core_bridge.py:406-409`）。
- 不要提交填好的密钥或 `config.qq.yaml`（`README.md:49`）。

### 6.5 控制台哪里安装

- 内核链：控制台「插件 → 内核插件」（`README.md:61`），后端 `POST /api/plugin-core/install`，接受**本地目录或单插件 zip**，先复制到 `.staging` 再原子换位，reload 失败会回滚到旧版本（`src/qq_app.py:6205-6224`、`src/plugin_core_bridge.py:359-364`、`:403-429`）。移除用 `POST /api/plugin-core/uninstall`（`src/qq_app.py:6226`），重载用 `POST /api/plugin-core/reload`（`:6244`），状态用 `GET /api/plugin-core/status`（`:6193`）。
- 旧链：控制台「插件 → 本地插件包」手动安装，不会自动安装（`README.md:58`）；用户插件复制到 `%LOCALAPPDATA%\WhaleGirlQQ\data\custom_plugins\<id>\`，停用不删文件（`README.md:59`）。
- 插件配置里的文件字段会把文件复制到 `data/plugin_uploads`，不会自动上传公网（`README.md:60`）。
